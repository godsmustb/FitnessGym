# CLAUDE.md: Build Rulebook for "Fitness Gym"

You are building a **native Android fitness companion** for one user: Nunna (ADHD, highly visual, non-coder, product/Agile background). The target device is a **Pixel 8**. It is **personal use only, not for sale, with no paywall**. The repo is **public and open source (AGPL-3.0)**: https://github.com/godsmustb/FitnessGym. Updates ship OTA through GitHub Releases and Obtainium.

Read these before writing code:
1. `docs/RESEARCH.md`: competitors, the top-10 complaints, evidence-based defaults, licensing
2. `docs/FEATURES.md`: the feature backlog with IDs and priorities
3. `docs/PLAN.md`: stack, data model, the animation approach, phases, owner decisions
4. `docs/CONTENT_SCHEMA.md` and `docs/MOTION_AUTHORING.md`: the exercise and animation data contracts
5. `BUILD_LOG.md`: what's done

Sister projects (pattern sources):
- `..\guitar-noodle`: native Kotlin, Obtainium OTA, GO button, module registry, error codes, health screen
- `..\french-coach`: Coach Québec, the PWA

## Non-negotiable rules

1. **Offline-first.** Everything works with no network (gym basements).
2. **Native stack.** Kotlin, Jetpack Compose (Material 3), Room (from P2). The figure engine lives in `:anim`, which is pure Kotlin/JVM with no Android imports. The same code renders on the phone (`FigureView`) and in the desktop PNG tool (`:preview`).
3. **Content is data.** Exercises are in `content/exercises.json`. They're generated by `tools/seed/build_db.py` from `motion_map.json`, `cues.json` and `authored.json`, so edit those and re-run the script. Animations are in `content/motions/*.json`. Adding an exercise or animation never needs code.
4. **Look before you ship an animation.** Render it with `ops\preview.ps1 <id>` and inspect the PNG:
   - correct anatomy (knee and elbow direction)
   - no floating or sinking
   - the glow peaks on the lift
5. **Muscle accuracy matters.** The figure glows `primary` (orange-red) and `secondary` (amber) muscle groups. Use the 19 group ids in CONTENT_SCHEMA.
6. **The user doesn't code.** Every step is a script in `ops/` or a button. Every error shows a code (`AREA-NNN`) and one plain-English fix.
7. **Licenses.** Record everything in `THIRD_PARTY.md`.
   - Never commit ExerciseDB / Gym visual GIFs.
   - Never commit secrets. The signing key lives in `%USERPROFILE%\.fitnessgym\` and reaches CI as the secrets `FG_KEYSTORE_B64` and `FG_KEYSTORE_PASSWORD`.
8. **Tests are part of "done".**
   - `:anim:test` passes: content schema, motion sanity and rig math.
   - The release APK builds.
   - The GitHub Action publishes a Release.
   - Report the results in a table in `BUILD_LOG.md`.
9. **Evidence-based training logic (P5).** A rules engine plans the training. An LLM may only explain it. See RESEARCH §5.
10. **Gamification on, guilt off.** No shame copy, and never block training.
11. **Cost discipline.** Use Sonnet subagents by default, at most 3 per phase, and a fresh session per phase.
